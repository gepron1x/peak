# АльпКлуб

Приложение для учета восхождений альпинистского клуба. Реализация технического задания
лабораторной работы №1: горы, альпинисты, восхождения, состав групп и отчеты.

Стек: Java 25, Spring Boot 4.1.2, Spring MVC + Thymeleaf, Spring Data JPA, PostgreSQL 18,
Flyway, Spring Security, Bootstrap 5, Gradle.

## Запуск

### Docker Compose

1. Скопируйте `.env.template` в `.env` и задайте пароли:

   ```
   DB_PASSWORD=<пароль PostgreSQL>
   APP_PASSWORD=<пароль учетной записи приложения>
   ```

2. Запустите приложение и базу:

   ```bash
   docker compose up -d --build
   ```

3. Откройте <http://localhost:8088> (или порт из `APP_PORT`) и войдите под учетной записью
   `APP_USERNAME` / `APP_PASSWORD`. Пароль обязателен и хранится только в `.env` или
   переменных окружения.

PostgreSQL публикуется на порту **5433**, чтобы не конфликтовать с локальной установкой
PostgreSQL на порту 5432. Внутри сети Docker приложение подключается к `db:5432`.

Порт приложения по умолчанию — 8088. Если он занят, задайте в `.env`:

```
SERVER_PORT=8090
APP_PORT=8090
```

`SERVER_PORT` используется при локальном запуске, `APP_PORT` — для публикации контейнера
(`http://localhost:8090`).

Для загрузки контрольного набора данных из ТЗ добавьте в `.env`:

```
APP_SEED_DEMO_DATA=true
```

Данные создаются только в пустой базе: горы М1/М2, альпинисты
Иванов Иван Иванович и Петрова Мария Сергеевна (с телефонами), восхождения В1–В3.

### Локально без Docker

Нужны Java 25 и PostgreSQL. Укажите параметры подключения в `.env` (`DB_URL`, `DB_USERNAME`,
`DB_PASSWORD`), затем:

```bash
./gradlew bootRun
```

Схема создается автоматически миграциями Flyway `V1__init.sql` и
`V2__climber_full_name_and_phone.sql`.

## Учетная запись

Доступ ко всем экранам закрыт формой входа. Единственная учетная запись оператора клуба
задается переменными окружения `APP_USERNAME` и `APP_PASSWORD`; в Git пароли не хранятся.

## Экраны и функции ТЗ

| Экран | Функции |
| --- | --- |
| Главная | Сводные показатели, быстрые переходы |
| Горы | Ф02 (добавление), Ф03 (изменение только без восхождений) |
| Гора → восхождения | Ф01 (восхождения выбранной горы по возрастанию начала с составом) |
| Альпинисты | Регистрация альпиниста (фамилия, имя, отчество, телефон, адрес), просмотр справочника |
| Восхождения | Ф08 (создание группы и восхождения), список всех восхождений |
| Восхождение → состав | Ф05 (добавление участника без дублей), завершение восхождения |
| Отчеты | Ф04 (альпинисты за период), Ф06 (завершенные восхождения по горам), Ф07 (восхождения за период), Ф09 (разные альпинисты на горе) |

Правила периода: границы `[A; B]` включают даты A и B, нижняя граница — `A 00:00`,
верхняя — `00:00` следующего дня после B. Запись попадает в отчет, если начало раньше
верхней границы, а окончание (для незавершенного восхождения — текущий момент) не раньше
нижней. Если A позже B, отчет не строится и показывается сообщение об ошибке.

Дополнительно проверяются: положительная высота, уникальность горы по названию, стране и
району без учета регистра, запрет будущих дат начала и окончания, окончание не раньше
начала, запрет повторного включения альпиниста в одно восхождение, запрет изменения горы,
на которую уже зарегистрированы восхождения, обязательность фамилии, имени, отчества,
корректного телефона и адреса альпиниста.

## Тесты

```bash
./gradlew test
```

`AcceptanceScenarioTest` проверяет бизнес-правила и расчеты отчетов на наборе, аналогичном
контрольному набору ТЗ. Тесты используют H2 в памяти и не требуют PostgreSQL.
